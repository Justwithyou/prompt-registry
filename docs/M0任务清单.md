## 0. 文档用途

本清单是《详细设计与开发排期计划》中 **M0（环境搭建 + 骨架）** 的落地细化版，并把上一轮讨论确定的落地思路（纵向切片、契约先行、核心逻辑人守、可演示可回退、M4 弹性缓冲）固化为可执行的规则与检查点。

使用方法：**M0 部分按任务逐行打勾执行；M1～M5 部分每天开工前看一次「今日检查点」，收工时做一次「收工 DOD」**。

## 1. M0 完成定义（Definition of Done）

只有下面全部为「是」，M0 才算完成，才允许进入 M1：

- [ ] 前端 `pnpm dev` 能启动 Vite + React，改动文件热更新生效。
- [ ] 后端 `cargo build` 通过，`pnpm tauri dev` 能打开桌面窗口。
- [ ] FSD 目录结构就绪：11 个 feature 切片 + entities + shared + app 边界清晰。
- [ ] Cargo Workspace 就绪：`core/storage/template/versioning/sync/crypto/ai/ipc` 8 个 crate 各就各位，workspace 编译通过。
- [ ] `core` crate 三大件定义完成：领域模型（`Prompt`/`Project`/`Tag`）、`AppError`、`PromptRepository` trait。
- [ ] 前端 IPC 契约类型就绪（`shared/api/commands.ts`），与后端命令签名一一对应。
- [ ] **纵向切片最简闭环打通**：前端能 `invoke('ping')` 拿到后端返回值并渲染到页面（证明 IPC 链路、状态注入、前端调用封装全部跑通）。

> 关键点：M0 不求任何业务功能，只求「一条从 React 按钮到 Rust 命令再回传的最小链路」被打通。这条链路是后续所有模块的地基，必须在这里就验证，不能留到 M1。

## 3. 进入研发后的每日检查点（M1～M5）

> 落地纪律：**每天开工前看「今日检查点」，收工必须过「收工 DOD」**，不达标不结束当天。

### 3.1 每日开工前（固定动作，约 10 分钟）

1. 从昨日的 `git tag`/提交确认基线：**今天在哪个可回退点之上开发**，先 `git status` 确认无隐藏 dirty 状态。
2. 确认今日任务属于哪个里程碑、依赖的任务是否已完成（对照排期 §6 任务看板）。
3. 若是**并行轨道**，先同步契约是否变更：前后端接口改动必须先改 `commands.ts` + Rust 结构体，再各自开工。
4. 明确今日「可演示」的产物是什么（一句话，能说给人听）。

### 3.2 收工 DOD（每天必过，缺一不可）

- [ ] 今日产物的核心路径已本地跑通一次（不只是「编译过」）。
- [ ] `cargo clippy` 无 warning（后端）、`tsc --noEmit` 无错误（前端）。
- [ ] 关键逻辑（加密/合并/契约/密钥派生）已人工 review 或留专项 review 待办，绝不裸交 AI 生成结果。
- [ ] 涉及数据库/契约变更的，迁移文件或 `commands.ts` 已同步，不存在「前端和后端各写各的」。
- [ ] 打 commit（建议每完成一个 M0-x 任务即 commit，不攒大 commit）。
- [ ] 若有破坏性改动，记录回退点。

### 3.3 各里程碑网关（Gate，跨日检查）

**M1（MVP，Day 1～3）——核心闭环网关**
- [ ] 创建 → 存 SQLite → 搜索 → 一键复制 全链路走通（纵向切片已扩展为真实业务切片）。
- [ ] `PromptRepository` 的 `SqlitePromptRepository` 实现完成，不绕开 trait 直连数据库。
- [ ] 列表/编辑器用真实数据可演示。
- ✅ 通过即打 `git tag m1`。

**M2（组织层，Day 4～5）——多维组织网关**
- [ ] 项目/标签/分类三者的关联关系在数据层正确（不出现脏关联）。
- [ ] 联合筛选（分类+标签+关键词）组合查询正确。
- ✅ 通过即打 `git tag m2`。

**M3（模板+版本，Day 6～8）——不可变校验网关**
- [ ] `prompt_versions` 只 INSERT 不 UPDATE/DELETE（数据不可变原则落地验证）。
- [ ] 版本 Diff + 回滚走通，回滚不丢原始版本。
- [ ] 模板变量提取与前端 Nunjucks 渲染结果一致。
- ✅ 通过即打 `git tag m3`。

**M4（安全+同步，Day 9～11）——弹性缓冲网关（重点）**
- [ ] SQLCipher 加密后，未解锁无法读取明文（做负向验证）。
- [ ] 密钥轮换流程：换口令只重新包装 Master Key，数据密钥不变。
- [ ] WebDAV 同步在至少 1 个真实服务商（坚果云/群晖/Nextcloud 任一）跑通一次。
- [ ] CRDT 冲突场景（两端同改）能触发人工兜底界面。
- ⚠️ **弹性决策点**：若 Day 11 仍未达「同步可用」，立即执行降级预案——把 P1「E2EE 同步」降级为「手动导入导出」先保 v1.0 上线，同步顺延 v1.1。**不卡在 M4 让整体延期。**
- ✅ 通过（或按预案降级）即打 `git tag m4`。

**M5（打磨+打包，Day 12～13）——可分发网关**
- [ ] 三平台（至少 Windows/macOS 任一 + 当前平台）安装包可安装运行。
- [ ] 核心逻辑单测覆盖率 > 70%。
- ✅ 通过即打 `git tag v1.0.0`。

## 4. 落地纪律（把思路固化成规则，贴在案头）

1. **切片优先**：任何新模块先打通一条「最小端到端切片」，再横向补全；禁止「把所有后端做完再写前端」的大瀑布。
2. **契约先行**：前后端接口 = 一份 `commands.ts`（TypeScript）+ 一份 Rust 结构体，先改契约再写实现，两边平行推进不互相等待。
3. **核心逻辑人守**：加密、CRDT 合并、密钥派生、IPC 契约这四类代码由人亲自把关，AI 只负责样板（CRUD、UI、测试、脚手架）。
4. **可回退**：每个任务一个 commit，每个里程碑一个 tag，任何破坏性改动前先留回退点。
5. **M4 是弹性区**：安全与同步允许降级交付，不因它阻塞 v1.0；「能存能搜能复制 + 本地加密」的优先级永远高于「多设备同步」。
6. **每天有可演示产物**：不存在「今天只搭了环境没看到东西」——即使是骨架，也要每天有一条看得见的进展。
