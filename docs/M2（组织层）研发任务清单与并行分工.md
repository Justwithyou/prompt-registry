## 0. 文档用途

M1 已跑通「提示词 CRUD + 明文 SQLite + FTS5 搜索 + 一键复制」的**核心单实体闭环**。本文档把 **M2（v1.0-a，Day 4~5，约 12 小时）** 的“组织层”功能拆成**可多任务并行**的任务清单。

M2 的核心增量是把 M1 的“扁平提示词列表”升级为**多维组织能力**：

| 功能域 | 排期 §2.3 | 说明 |
|---|---|---|
| 分类 + 标签 | 2.3.1（4h） | 树形分类、层级标签、标签云、多选/联合筛选 |
| 项目管理 | 2.3.2（4h） | 项目 CRUD、多对多关联、按项目浏览 |
| 收藏 / 置顶 / 评分 | 2.3.3（2h） | 卡片快捷操作 + 列表排序 |
| 批量操作 | 2.3.4（2h） | 多选、批量打标签/移动项目/删除 |

并行机制与 M1 一致：**先冻结契约（唯一串行前置，含数据库 schema 变更），之后 A/B/C/D 四条轨道互不依赖、同时开工，最后集成收口。**

## 1. M2 完成定义（DoD）

全部为“是”才算 M2 完成，才打 `git tag m2`：

- [ ] 分类：可建树形分类、拖拽排序，按分类筛选提示词。
- [ ] 标签：可建层级标签（`场景/客服`）、标签云视图、多选筛选。
- [ ] 项目：项目 CRUD，提示词可多对多关联项目，侧边栏“按项目浏览”。
- [ ] 收藏 / 置顶 / 评分：卡片上可直接勾选收藏/置顶、快捷打分，列表按此排序。
- [ ] 批量操作：多选模式，批量打标签、移动项目、删除。
- [ ] 联合筛选：分类 + 标签 + 关键词 + 收藏/置顶 的 SQL 组合查询走通。
- [ ] 新增表/Repository/IPC/store 类型与 `tsc --noEmit`、`cargo clippy` 全绿；`cargo test -p storage` 全绿。
- [ ] ✅ 全部达成 → `git checkout main && git merge m2-org` 后打 `git tag m2`。

> 范围提醒：M2 仍用**明文 SQLite**（rusqlite `bundled`），不做 SQLCipher 加密，也不做模板/版本（M3）、同步（M4）。本里程碑只做“组织层”，聚焦多维分类/标签/项目与批量管理。

## 3. Phase 0 · 契约冻结（串行前置，唯一阻塞点）

> **没完成前四轨都不许开工。** 与 M1 不同的是，M2-P1 除了命令签名，还要**冻结数据库 schema 变更**（新增 4 张表 + 2 张关联表），因为 data 层迁移是所有轨道的地基。

### 3.1 需拍板的决策点（人定，AI 生成）

| 决策 | 推荐 | 说明 |
|---|---|---|
| 分类结构化 | **方案 A：`categories` 表 + `prompts.category_id` 外键** | 树形 + 拖拽排序需要稳定 ID；旧 `prompts.category` 字符串在迁移中回填为默认分类，保留兼容读 |
| 收藏/置顶/评分 | **复用 M1 已有字段**（`is_pinned/is_favorite/rating`），M2 只补“卡片快捷操作 + 排序”，不重建字段 | 避免与 M1 重复；本里程碑不新增字段 |
| 批量操作范围 | 本里程碑只做“批量打标签 / 移动项目 / 删除”，不做批量编辑正文/重命名 | 控制范围，批量编辑正文归后续 |

### 3.2 锁定内容（写死在文档里，避免并行漂移）

**新增模型（`core/src/models/`）**：

```
Project { id, name, description, color, created_at, updated_at }
Tag     { id, name, parent_id, color, created_at }
Category{ id, name, parent_id, sort_order, created_at }
```

**新增迁移（`storage/migrations/0002_organize.sql`）**：

```sql
-- 分类（树形，支持拖拽排序）
CREATE TABLE categories (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  parent_id TEXT REFERENCES categories(id),
  sort_order INTEGER DEFAULT 0,
  created_at TEXT NOT NULL
);

-- 项目
CREATE TABLE projects (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  color TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 提示词-项目 多对多
CREATE TABLE prompt_projects (
  prompt_id TEXT NOT NULL REFERENCES prompts(id),
  project_id TEXT NOT NULL REFERENCES projects(id),
  PRIMARY KEY (prompt_id, project_id)
);

-- 标签（层级：场景/客服）
CREATE TABLE tags (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  parent_id TEXT REFERENCES tags(id),
  color TEXT,
  created_at TEXT NOT NULL
);

-- 提示词-标签 多对多
CREATE TABLE prompt_tags (
  prompt_id TEXT NOT NULL REFERENCES prompts(id),
  tag_id TEXT NOT NULL REFERENCES tags(id),
  PRIMARY KEY (prompt_id, tag_id)
);

CREATE INDEX idx_categories_parent ON categories(parent_id);
CREATE INDEX idx_tags_parent ON tags(parent_id);
CREATE INDEX idx_prompt_projects_project ON prompt_projects(project_id);
CREATE INDEX idx_prompt_tags_tag ON prompt_tags(tag_id);
```

**命令清单（`#[tauri::command]` ↔ `commands.ts`）**：

| 命令 | 签名 |
|---|---|
| `list_categories` | `() -> Vec<Category>` |
| `create_category` | `(input: CreateCategoryInput) -> Category` |
| `update_category` | `(id, input: UpdateCategoryInput) -> Category` |
| `delete_category` | `(id) -> ()` |
| `list_projects` | `() -> Vec<Project>` |
| `create_project` | `(input: CreateProjectInput) -> Project` |
| `update_project` | `(id, input: UpdateProjectInput) -> Project` |
| `delete_project` | `(id) -> ()` |
| `list_tags` | `() -> Vec<Tag>` |
| `create_tag` | `(input: CreateTagInput) -> Tag` |
| `update_tag` | `(id, input: UpdateTagInput) -> Tag` |
| `delete_tag` | `(id) -> ()` |
| `set_prompt_relations` | `(id, relations: PromptRelationsInput) -> Prompt` |
| `batch_update_prompts` | `(ids, batch: BatchUpdateInput) -> ()` |

**扩展 `PromptQuery`**（`get_prompts` 复用）：新增 `projectId?`、`tagIds?`、`categoryId?`、`isFavorite?`、`sortBy?`（`updatedAt|rating|createdAt`）字段。

**`PromptRelationsInput`**：一次性更新某条提示词的 `project_ids / tag_ids / is_pinned / is_favorite / rating`（供卡片快捷操作与元数据面板复用）。

**`BatchUpdateInput`**：`add_tag_ids? / remove_tag_ids? / set_project_id? / delete?: boolean`（批量操作用）。

## 9. 并行协作约束（务必遵守）

1. **文件归属唯一**：每个文件只归一条轨道改。跨轨文件（`commands.ts`、`PromptRepository` trait、模型、`0002_organize.sql`）在 Phase 0 冻结后默认只读，需改动先广播。
2. **提交粒度**：按 `M2-x` 一个 commit；建议每轨一个 feature 分支（`m2-org/a-storage`、`m2-org/b-ipc`…），集成阶段合并回 `m2-org`。
3. **迁移文件是地基**：`0002_organize.sql` 一旦冻结，A 之外的轨道不得改；若需要回填旧 `category` 字符串，只在 A2 做一次，广播结果。
4. **契约变更广播**：Phase 0 后若改模型/命令签名，先通知其余三轨。
5. **联调段人工主导**：多对多关系、批量事务这些易错接缝，人先定位再让 AI 改。
6. **可回退**：Phase 0 完、四轨各自完、集成完，各打一个轻量 commit 作为回退点。
