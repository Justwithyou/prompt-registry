## 0. 文档用途

M1 已跑通「提示词 CRUD + 明文 SQLite + FTS5 搜索 + 一键复制」的**核心单实体闭环**；M2 补齐了「分类 / 标签 / 项目 / 收藏置顶评分 / 批量操作」的**多维组织层**。本文档把 **M3（v1.0-b，Day 6～8，约 18 小时）** 的「模板 + 版本」能力拆成**可多任务并行**的任务清单。

M3 的两大增量：

| 功能域 | 排期 §2.4 | 说明 |
|---|---|---|
| 模板引擎 | 2.4.1（8h） | `{{变量}}` 提取、变量填写面板、Nunjucks 渲染预览、一键复制 |
| 版本控制 | 2.4.2（10h） | 保存自动记版本、Diff 词级对比、历史时间轴、回滚 |

并行机制延续 M1/M2：**先冻结契约与迁移（唯一串行前置），之后 A/B/C/D 四轨互不依赖、同时开工，最后集成收口。**

## 1. M3 完成定义（DoD）

全部为“是”才算 M3 完成，才打 `git tag m3`：

- [ ] 模板：输入含 `{{变量名}}` 的正文，可自动提取变量列表。
- [ ] 模板：有变量填写面板，填写后实时预览渲染结果，可一键复制。
- [ ] 版本：每次保存提示词，自动在 `prompt_versions` 追加一条历史版本（语义化版本号递增）。
- [ ] 版本：有历史时间轴视图（版本号 / 变更摘要 / 时间戳）。
- [ ] Diff：选中两个版本可并排展示词级差异（新增绿 / 删除红）。
- [ ] 回滚：从任一历史版本回滚，生成**新版本**（追加式，不覆盖历史）。
- [ ] 新增 `prompt_versions` 迁移、`crates/template` 提取器、VersionRepository/IPC/store，`tsc --noEmit`、`cargo clippy` 全绿；`cargo test -p storage` 全绿。
- [ ] ✅ 全部达成 → `git checkout main && git merge m3-template-versioning` 后打 `git tag m3`。

> 范围提醒：M3 仍用**明文 SQLite**，不做加密（M4）；不碰同步（M4）。只做「模板 + 版本」两件事。

## 3. Phase 0 · 契约冻结（串行前置，唯一阻塞点）

> **没完成前四轨都不许开工。** 与 M2 类似，M3-P1 除命令签名外，还要**冻结 `prompt_versions` 表迁移**与**新增 `crates/template` 提取器契约**。

### 3.1 需拍板的决策点（人定，AI 生成）

| 决策 | 推荐 | 说明 |
|---|---|---|
| 模板渲染位置 | **前端 Nunjucks** | 避免 Rust 侧引入 JS 运行时；Rust 侧保留 `tera` 作为备选但 M3 不接入 |
| 变量提取位置 | **Rust `crates/template` extractor**（`extract_variables` 命令） | 排期 §2.4.1 已定；正则 `\{\{(\w+)\}\}`，返回 `VariableDefinition[]` |
| 版本号语义化规则 | `主.次.补丁`（默认 `0.1.0` 起，每次保存补丁 +1） | 规则在 VersionRepository 内固化 |
| 自动记录触发时机 | `update_prompt` 保存时（防抖回调触发）自动插一条 | 与 M1 防抖保存接缝对齐；显式 `创建快照` 命令留给后续 |
| Diff 计算位置 | 前端 `diff` 库 `diffWords` | 后端只存原文，返回版本列表；词级对比由前端完成 |

### 3.2 锁定内容（写死，避免并行漂移）

**新增模型（`core/src/models/`）**：

```
// templates（模板引擎产物）
VariableDefinition { name, default_value?, options?, description? }

// versions（版本历史）
PromptVersion { id, prompt_id, version, content, change_summary?, created_at }
```

**新增迁移（`storage/migrations/0003_versioning.sql`）**：

```sql
CREATE TABLE prompt_versions (
  id TEXT PRIMARY KEY,
  prompt_id TEXT NOT NULL REFERENCES prompts(id),
  version TEXT NOT NULL,
  content TEXT NOT NULL,
  change_summary TEXT,
  created_at TEXT NOT NULL
);

CREATE INDEX idx_prompt_versions_prompt ON prompt_versions(prompt_id, created_at DESC);
```

**新增 crate（`crates/template`）**：

```rust
// crates/template/src/extractor.rs
pub struct VariableDefinition {
    pub name: String,
    pub default_value: Option<String>,
    pub options: Option<Vec<String>>,
    pub description: Option<String>,
}
pub fn extract_variables(content: &str) -> Vec<VariableDefinition>;
```

**命令清单（`#[tauri::command]` ↔ `commands.ts`）**：

| 命令 | 签名 |
|---|---|
| `extract_variables` | `(content: String) -> Vec<VariableDefinition>` |
| `list_prompt_versions` | `(prompt_id: String) -> Vec<PromptVersion>` |
| `get_prompt_version` | `(version_id: String) -> PromptVersion` |
| `rollback_prompt_version` | `(prompt_id: String, version_id: String) -> Prompt` |

**自动版本记录约定**：`update_prompt` 在更新前把**旧 content**（含旧正文，change_summary 由前端传入的变更说明或后端生成）写入 `prompt_versions`，版本号按 `主.次.补丁` 递增。前端 `promptStore` 的防抖保存成功后，需重新拉取该提示词的版本列表。

## 9. 并行协作约束（务必遵守）

1. **文件归属唯一**：每个文件只归一条轨道改。跨轨文件（`commands.ts`、`version_repository` trait、`prompt versions` 模型、`0003_versioning.sql`）Phase 0 冻结后只读，需改动先广播。
2. **提交粒度**：按 `M3-x` 一个 commit；建议每轨一个 feature 分支（`m3-template-versioning/a-storage`、`.../b-ipc`、`.../d1-template-ui` 等），集成阶段合并回 `m3-template-versioning`。
3. **两个新依赖是地基**：`nunjucks` / `diff` 由 C 轨统一安装并提交 `package.json` + `pnpm-lock.yaml`，D 轨只 import 不重复装。
4. **自动版本记录接缝**：`update_prompt` 的版本记录（A5）与前端防抖保存（C2）是易错接缝，联调段人先验一遍事务一致性。
5. **回滚是追加式**：回滚 = 生成新版本，绝不允许 `DELETE/UPDATE` 覆盖历史记录。
6. **契约变更广播**：Phase 0 后改模型/命令签名，先通知其余三轨。
7. **可回退**：Phase 0 完、各轨完、集成完，各打一个轻量 commit 作为回退点。
