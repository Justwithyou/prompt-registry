## 1. M4 完成定义（DoD）

全部为“是”才算 M4 完成，才打 `git tag m4`：

- [ ] 密钥：首次设置口令后，数据库落地为 **SQLCipher 加密**，无口令无法读库。
- [ ] 密钥：支持锁定 / 解锁 / 修改口令；修改口令只重新包装 Master Key，数据密钥不变（密钥轮换）。
- [ ] 密钥：Master Key 可存 OS 钥匙串（可选自动解锁）。
- [ ] 同步：配置 WebDAV（坚果云 / 群晖 / Nextcloud）后可一键同步。
- [ ] 同步：本地变更 → AES-256-GCM 加密 → 上传；拉取远端变更 → 解密 → 合并写回本地。
- [ ] 冲突：多设备同改一条提示词，按 HLC + 字段级 LWW 合并，不丢数据、不产生硬冲突。
- [ ] 版本历史在同步下保持追加式，无冲突。
- [ ] `crypto`/`sync` crate 实现 + SQLCipher 集成，`tsc --noEmit`、`cargo clippy` 全绿；`cargo test -p crypto -p sync -p storage` 全绿。
- [ ] ✅ 全部达成 → `git checkout main && git merge m4-crypto-sync` 后打 `git tag m4`。

> 范围提醒：AI 辅助（`crates/ai`）是 P2 之后的事，M4 不做；打磨 / 打包 / 自动更新归 M5。

**并行可行性依据**：M4 的并行靠**trait 契约隔离**实现——
- 轨道 B（SQLCipher）依赖「打开/锁定数据库所需的 Master Key 接口」，用 A 冻结的 `VaultProvider` trait 解耦，不依赖 A 的 Argon2id 具体实现。
- 轨道 C（同步）依赖「加密管道接口」，用 A 冻结的 `SyncCipher` trait 解耦，不依赖 A 的 AES-GCM 具体实现。
- 因此 A/B/C 三条后端轨道在 P1 冻结后互不阻塞；D/E 依赖契约签名，也可并行。

## 3. Phase 0 · 契约冻结（串行前置，唯一阻塞点）

> **没完成前五轨都不许开工。** M4-P1 重点是冻结**三个新 trait 契约**与**SQLCipher 迁移策略**，这是唯一需要“人拍板 + 想清楚”的串行环节。

### 3.1 需拍板的决策点（人定，AI 生成）

| 决策 | 推荐 | 说明 |
|---|---|---|
| SQLCipher 迁移策略 | **首次设置口令时 `PRAGMA rekey` 现库**，无口令保持明文 | 平滑升级，不破坏 M1～M3 已有数据 |
| SQLCipher 依赖 | `rusqlite` 切到 `bundled-sqlcipher`，锁定 `libsqlite3-sys` 版本 | 排期风险表已列：跨平台编译可能失败，需锁版本 |
| 加密算法参数 | Argon2id（内存 64MB / 迭代 3 / 并行 1 / 盐 32B）；AES-256-GCM；HKDF-SHA256 | 排期 §2.5.1/2.5.2 已定 |
| WebDAV 客户端 | `reqwest`（PUT/GET/PROPFIND/MKCOL），Basic Auth | 兼容坚果云/群晖/Nextcloud |
| OS 钥匙串 | `keyring` crate（轻量） | 备选 Tauri stronghold 插件，M4 先用 keyring |
| CRDT 粒度 | **字段级 LWW**（title/content/description 等字段粒度），版本历史追加式 | 排期 §2.5.3 已定 |

### 3.2 锁定内容（写死，避免并行漂移）

**三个新 trait（`core/src/traits/`）**：

```rust
// 密钥/保险库：轨道 B/C 都只依赖它，不依赖 Argon2id 实现
pub trait VaultProvider {
    fn setup(&self, password: &str) -> Result<(), AppError>;
    fn unlock(&self, password: &str) -> Result<(), AppError>;
    fn lock(&self) -> Result<(), AppError>;
    fn change_password(&self, old_pw: &str, new_pw: &str) -> Result<(), AppError>;
    fn master_key(&self) -> Result<[u8; 32], AppError>;
}

// 同步加密管道：轨道 C 依赖它加密/解密同步数据包
pub trait SyncCipher {
    fn encrypt(&self, plaintext: &[u8], sync_key: &[u8; 32]) -> Result<EncryptedPayload, AppError>;
    fn decrypt(&self, payload: &EncryptedPayload, sync_key: &[u8; 32]) -> Result<Vec<u8>, AppError>;
}

// 同步引擎：轨道 D 依赖它；A/B/C 各自实现内部细节
pub trait SyncEngine {
    fn collect_pending(&self) -> Result<Vec<SyncLogEntry>, AppError>;
    fn sync_once(&self, remote: &dyn RemoteStore) -> Result<SyncResult, AppError>;
}
```

**关键模型（`core/src/models/`）**：

```
EncryptedPayload { version, salt, nonce, ciphertext }
SyncLogEntry     { id, entity_type, entity_id, operation, payload, hlc, device_id }
SyncConfig       { url, username, token?, enabled }
SyncStatus       { last_sync_at?, pending_changes, device_id }
SyncResult       { pushed, pulled, merged }
```

**命令清单（`#[tauri::command]` ↔ `commands.ts`）**：

| 命令 | 签名 |
|---|---|
| `setup_vault` | `(password: String) -> ()` |
| `unlock_vault` | `(password: String) -> ()` |
| `lock_vault` | `() -> ()` |
| `change_password` | `(old_pw: String, new_pw: String) -> ()` |
| `is_locked` | `() -> bool` |
| `configure_sync` | `(config: SyncConfig) -> ()` |
| `sync_now` | `() -> SyncResult` |
| `get_sync_status` | `() -> SyncStatus` |

## 10. 并行协作约束（务必遵守）

1. **trait 契约是唯一并行粘合剂**：`VaultProvider`/`SyncCipher`/`SyncEngine` 在 P1 冻结后只读，任何签名变更必须先广播到 B/C/D 轨。
2. **文件归属唯一**：每个文件只归一条轨道；跨轨文件（`Cargo.toml`、`Cargo.lock`、`commands.ts`、trait/model 文件）P1 冻结后只读。
3. **SQLCipher 是风险点**：`bundled-sqlcipher` 跨平台编译可能失败，B1 发现即上报；锁 `libsqlite3-sys` 版本后全轨统一。
4. **安全参数不得私自改**：Argon2id 参数、盐/Nonce 长度、HKDF domain，任何改动需在 P1 广播并达共识（涉及已加密数据兼容性）。
5. **同步不丢数据**：CRDT 合并必须可重放、无副作用；联调前先备份本地库。
6. **密钥绝不落库明文**：Master Key 只进内存与 OS 钥匙串，日志 / sync_log 不写 key。
7. **提交粒度**：按 `M4-x` 一个 commit；建议每轨 feature 分支（`m4-crypto-sync/a-crypto`、`.../b-sqlcipher`、`.../c-sync` 等）集成时合并回 `m4-crypto-sync`。
8. **可回退**：Phase 0 完、各轨完、集成完，各打一个轻量 commit 作为回退点。
