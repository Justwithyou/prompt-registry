# UI 交互设计优化建议

> 本文档记录对当前版本界面的一次系统性 UI/UX 评审结论，并跟踪各条建议的落实状态。
> 状态取值：`待评审` / `已验证通过` / `实施中` / `待验证` / `已验证通过` / `未通过（调整中）`。

## 优化原则

1. 视觉更舒适：清晰的字号层级、统一的圆角与配色、适当的呼吸感。
2. 交互更流畅：关键操作有即时反馈，危险操作有统一确认，弹窗关闭行为一致。
3. 操作更简单：减少重复入口，次要操作收敛，主次分明。

## 验证记录

### 前端（本次改动全部为 React/TS/CSS）

- `npx tsc --noEmit` —— ✅ 通过（无类型错误）。
- `cargo check` —— ✅ 通过（后端编译正常，确认前端改动未破坏构建）。

### 后端测试（`cargo test`）

- 下游 crate 单元/集成测试全部通过：`ai`(3)、`crypto`(15)、`export`(4)、`storage`(26)、`sync`(12)、`template`(8)、`versioning`/`ipc`/`cli`/`core` 等。
- ⚠️ 两处**既存**问题（与本次 UI 改动无关，改动未触碰任何 Rust 文件）：
  1. 顶层 `prompt-manager` 的 Tauri mock 集成测试二进制启动即报 `STATUS_ENTRYPOINT_NOT_FOUND (0xc0000139)`，属 Windows DLL 入口点加载问题（疑似环境：本地 `OpenSSL-Win64` 被加入全局链接搜索路径 + `windows` crate 0.52/0.53 双版本并存）。
  2. `core` crate 的 doctest 报 `cannot find write/fmt in core`，由“crate 命名为 `core` 与标准库 `core` 冲突 + thiserror 宏展开”导致，属命名冲突既存问题。

> 结论：本轮 7 条 UI 优化已完成并通过前端验证（`tsc` + `cargo check` + 下游 crate 测试）；两条 `cargo test` 失败均为 Rust 侧既存/环境问题，未受本轮前端改动影响。是否处理这两处，待与用户确认后另行排期。
