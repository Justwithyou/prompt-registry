# 个人提示词管理平台 架构设计方案

**文档版本**：V1.0
**日期**：2026-09-28
**状态**：草案
**关联文档**：《个人提示词管理平台 BRD》V1.0

## 1. 架构概述

### 1.1 设计目标

本架构方案基于 BRD 中定义的功能需求与技术选型，实现以下目标：

- **本地优先**：所有数据默认存储在本地，无需联网即可完成全部核心操作。
- **隐私安全**：数据库加密、端到端加密同步、零知识服务器。
- **模块解耦**：提示词库、模板引擎、版本控制、同步、安全各自独立，可独立测试和替换。
- **平滑扩展**：从个人使用到团队协作，从桌面端到浏览器插件/CLI，架构不阻塞。
- **可维护**：清晰的层次边界和 IPC 契约，降低长期维护成本。

### 1.2 架构风格

采用**分层架构 + 模块化**的组合：

- **分层**：前端层（React）→ IPC 层（Tauri Commands/Events）→ 后端层（Rust）→ 数据层（SQLCipher）。
- **模块化**：后端按业务域拆分为独立 Rust crate，前端按功能切片（Feature-Sliced Design）。

### 1.4 关键架构决策

| 决策编号 | 决策 | 理由 | 备选方案 |
|---|---|---|---|
| AD-01 | 选用 Tauri 2.x 而非 Electron | 体积小（~5MB vs ~150MB）、内存占用低、Rust 安全后端 | Electron（体积大但生态成熟） |
| AD-02 | 选用 SQLCipher 而非应用层字段加密 | 全库文件级加密，覆盖所有查询路径，无遗漏风险 | 字段级加密（性能开销分散但实现复杂） |
| AD-03 | 选用 rusqlite 插件而非官方 sqlx 插件 | rusqlite 通过 `bundled-sqlcipher` feature 原生支持 SQLCipher，官方 sqlx 插件尚未内置该支持 | tauri-plugin-sql（需手动替换 libsqlite3-sys） |
| AD-04 | 同步层选用 WebDAV + E2EE 而非自建云服务 | 零知识，用户掌控数据，无需维护服务器 | 自建 API 服务器（运维成本高） |
| AD-05 | 冲突解决采用 CRDT + HLC | 离线优先架构下自动合并，无需中心协调 | 最后写入胜出（LWW，会丢失数据） |
| AD-06 | 密钥管理采用“包装主密钥”设计 | 随机主密钥加密数据，口令派生 KEK 包装主密钥，便于密钥轮换 | 直接用口令派生密钥（轮换需全量重新加密） |
| AD-07 | 模板引擎选用 Nunjucks | 支持变量注入与条件/循环逻辑，已在多个提示词框架中验证 | 自研模板引擎（工作量大） |

### 1.5 架构原则

- **依赖方向**：上层依赖下层，下层不感知上层。Rust 后端不依赖 React 前端的具体实现。
- **IPC 契约优先**：前后端通过明确定义的 TypeScript 接口和 Rust 结构体通信，接口变更需同步更新两端。
- **故障隔离**：同步、AI 辅助等非核心功能异常不影响本地核心使用。
- **数据不可变**：版本历史采用追加式日志，修改不覆盖原始数据。

## 3. 前端架构设计

### 3.1 目录结构

前端采用 **Feature-Sliced Design（FSD）** 模式，按业务功能切片组织代码，每个切片内部高内聚，切片之间通过明确的公开 API 通信。参考了 ZeroLimit 等 Tauri + React 项目的组织方式。

```
src/
├── app/                        # 应用入口、路由、全局 Provider
│   ├── App.tsx
│   ├── router.tsx
│   └── providers.tsx
├── features/                   # 功能切片（按业务域）
│   ├── prompt-library/         # 提示词库
│   │   ├── components/         # 切片私有组件
│   │   ├── hooks/              # 切片私有 hooks
│   │   ├── stores/             # 切片状态
│   │   ├── api/                # IPC 调用封装
│   │   ├── types/              # 切片类型定义
│   │   └── index.ts            # 公开 API（统一导出）
│   ├── prompt-editor/          # 提示词编辑器
│   ├── template-engine/        # 模板变量编辑与使用
│   ├── version-control/        # 版本对比与回滚
│   ├── project-management/     # 项目管理
│   ├── tag-management/         # 标签管理

│   ├── ai-assistant/           # AI 辅助
│   ├── import-export/          # 导入导出
│   └── settings/               # 设置

│   │   ├── Button/
```

**关键约束**：

- `features/` 之间不可直接互相 import，必须通过 `entities/` 或 `shared/` 间接依赖。
- `shared/` 不可依赖 `features/` 或 `entities/`。
- 每个 feature 的 `index.ts` 只导出公开 API，内部实现不对外暴露。
- 模板引擎作为 `shared` 级别的服务，不单独放在 `features` 中。

### 3.2 状态管理设计

采用 **Zustand** 进行轻量状态管理，按领域拆分多个 store，避免单一巨型 store。

```typescript
// features/prompt-library/stores/promptStore.ts
interface PromptStore {
  prompts: Prompt[];
  selectedPromptId: string | null;
  filters: PromptFilters;
  isLoading: boolean;

  fetchPrompts: (filters?: PromptFilters) => Promise<void>;
  selectPrompt: (id: string) => void;
  createPrompt: (data: CreatePromptInput) => Promise<Prompt>;
  updatePrompt: (id: string, data: UpdatePromptInput) => Promise<void>;
  deletePrompt: (id: string) => Promise<void>;
}
```

**Store 划分**：

| Store | 所属 Feature | 职责 |
|---|---|---|
| promptStore | prompt-library | 提示词列表、选中状态、筛选条件 |
| editorStore | prompt-editor | 编辑中内容、草稿、保存状态 |
| templateStore | template-engine | 变量定义、变量值、预览结果 |
| versionStore | version-control | 版本列表、Diff 目标版本 |
| projectStore | project-management | 项目列表、当前项目 |
| tagStore | tag-management | 标签树、选中标签 |
| syncStore | sync | 同步状态、上次同步时间、冲突列表 |
| settingsStore | settings | 用户偏好、加密状态、模型配置 |

**状态同步策略**：

- 前端 Zustand store 与 Rust 后端之间通过 `tauri-plugin-sync-state` 插件实现双向、类型键控的状态同步，后端状态变更（如后台同步完成）可自动触发前端 store 更新。
- 对于非实时的数据变更，使用 Tauri 的 `emit()`/`listen()` 事件机制通知前端刷新。

### 3.3 路由设计

使用 React Router 8.4.0，采用**嵌套路由**结构：

```
/                           → 重定向到 /prompts
/prompts                    → 提示词列表（默认卡片视图）
/prompts/:id                → 提示词详情/编辑
/prompts/:id/versions       → 版本历史
/prompts/:id/versions/:vid  → 指定版本详情
/projects                   → 项目列表
/projects/:id               → 项目详情（包含该项目下提示词）
/tags                       → 标签管理
/search                     → 高级搜索
/sync                       → 同步配置与状态
/settings                   → 设置
  ├── /settings/general     → 通用
  ├── /settings/security    → 安全与加密
  ├── /settings/models      → AI 模型配置
  └── /settings/appearance  → 外观
```

### 3.4 组件设计原则

- **原子化**：基础 UI 组件（Button、Input、Card、Dialog 等）放在 `shared/ui/`，不含业务逻辑。
- **业务组件**：带业务逻辑的组件放在对应 feature 的 `components/` 目录下。
- **容器/展示分离**：复杂页面采用 Container 组件管理数据和逻辑，Presentational 组件负责渲染。
- **虚拟滚动**：提示词列表和版本历史等长列表使用虚拟滚动，确保万级数据下流畅。

### 3.5 IPC 通信设计

Tauri v2 提供三种 IPC 原语：Commands（请求-响应）、Events（单向通知）、Channels（高频流式传输）。

**使用场景划分**：

| IPC 原语 | 方向 | 使用场景 | 示例 |
|---|---|---|---|
| Commands (`invoke`) | 前端 → Rust → 前端 | 数据查询、增删改、触发操作 | 获取提示词列表、保存编辑、触发同步 |
| Events (`emit`/`listen`) | 双向（单向发送） | 后台事件通知、状态广播 | 同步完成通知、AI 生成进度 |
| Channels (`Channel<T>`) | Rust → 前端 | 高频流式数据 | AI 生成流式输出、同步进度百分比 |

**IPC 契约定义**：

所有命令通过统一的 TypeScript 类型定义管理：

```typescript
// shared/api/commands.ts
export interface CommandMap {
  // 提示词管理
  get_prompts: { args: PromptQuery; result: Prompt[] };
  get_prompt: { args: { id: string }; result: PromptDetail };
  create_prompt: { args: CreatePromptInput; result: Prompt };
  update_prompt: { args: UpdatePromptInput; result: Prompt };
  delete_prompt: { args: { id: string }; result: void };

  // 模板
  render_template: { args: { templateId: string; variables: Record<string, string> }; result: string };
  extract_variables: { args: { content: string }; result: VariableDefinition[] };

  // 版本
  get_versions: { args: { promptId: string }; result: VersionSummary[] };
  diff_versions: { args: { promptId: string; v1: string; v2: string }; result: DiffResult };
  rollback_version: { args: { promptId: string; version: string }; result: Prompt };

  // 同步
  sync_now: { args: void; result: SyncResult };
  get_sync_status: { args: void; result: SyncStatus };

  // 加密与安全
  unlock_vault: { args: { password: string }; result: boolean };
  lock_vault: { args: void; result: void };
  change_master_password: { args: { current: string; newPassword: string }; result: void };
}
```

**错误处理**：

Rust 端使用 `thiserror` 定义统一的 `AppError` 枚举，返回 `Result<T, AppError>`，前端通过 try-catch 捕获并展示用户友好的错误信息。

### 4.2 核心 Crate 职责

| Crate | 职责 | 对外接口 | 依赖 |
|---|---|---|---|
| `core` | 领域模型、错误类型、Repository trait | `Prompt`, `Project`, `Tag`, `AppError`, `PromptRepository` | 无 |
| `storage` | SQLCipher 数据持久化 | `SqlitePromptRepository`, `Migrations` | core |

## 5. 安全架构设计

### 5.1 密钥管理层级

采用**包装主密钥（Wrapped Master Key）** 设计，参考了 Mini Diarium、OtpVault 等本地加密应用的架构：

```
用户口令 (Master Password)
    │
    ▼ Argon2id (64MB 内存, 3 次迭代, 并行度 1, 32 字节随机盐)
    │
    ▼ KEK (Key Encryption Key, 256-bit)
    │
    ├── 包装 → Master Key (随机生成的 256-bit 数据加密密钥)
    │              │
    │              ├── 加密 → SQLCipher 数据库
    │              ├── 加密 → 同步数据包 (AES-256-GCM)
    │              └── 加密 → 加密备份文件
    │
    └── 存储 → OS 钥匙串 (Keychain/Credential Manager/Secret Service)
```

**Argon2id 参数**：内存 64MB（65536 KiB），迭代 3 次，并行度 1，盐 32 随机字节。

**密钥派生流程**：

```rust
// crates/crypto/src/kdf.rs
pub fn derive_key(password: &str, salt: &[u8]) -> Result<[u8; 32], AppError> {
    let params = argon2::Params::new(65536, 3, 1, Some(32))
        .map_err(|e| AppError::Crypto(e.to_string()))?;
    let argon2 = Argon2::new(Algorithm::Argon2id, Version::V0x13, params);
    let mut key = [0u8; 32];
    argon2.hash_password_into(password.as_bytes(), salt, &mut key)
        .map_err(|e| AppError::Crypto(e.to_string()))?;
    Ok(key)
}
```

**为什么采用包装主密钥设计**：如果直接用口令派生的密钥加密数据，用户更换口令时需重新加密全部数据。采用包装主密钥后，更换口令只需重新包装主密钥，数据加密密钥不变，大幅降低密钥轮换成本。

**密钥轮换流程**：

1. 用户输入当前口令和新口令。
2. 用旧口令派生的 KEK 解包 Master Key。
3. 用新口令派生的 KEK 重新包装 Master Key。
4. 更新 OS 钥匙串中的包装结果。
5. 同步数据的加密密钥不变，无需重新上传。

### 5.2 数据库加密

SQLCipher 对数据库文件进行**全页加密**，加密覆盖数据库文件中的所有页面（包括索引、临时文件、WAL 日志）。数据库密钥由 Master Key 通过 HKDF-SHA256 派生，与同步加密密钥隔离。

```rust
// crates/storage/src/sqlite/connection.rs
pub fn open_encrypted_db(path: &Path, master_key: &[u8; 32]) -> Result<Connection, AppError> {
    // 从 Master Key 派生数据库专用密钥
    let db_key = hkdf_expand(master_key, b"database-encryption-key")?;
    let conn = Connection::open(path)?;
    // 设置 SQLCipher 加密密钥
    conn.pragma_update(None, "key", &hex::encode(&db_key))?;
    // 验证密钥正确性
    conn.pragma_query_value(None, "cipher_version", |row| row.get::<_, String>(0))?;
    Ok(conn)
}
```

### 5.3 端到端加密同步管道

同步数据的加密完全在本地完成，WebDAV 服务器只存储密文，实现零知识。

**加密管道流程**：

```
本地变更 → 序列化为 JSON → AES-256-GCM 加密 → 打包 (salt + nonce + ciphertext)
    → WebDAV PUT → 服务器存储密文

WebDAV GET → 解包 → AES-256-GCM 解密 → JSON 反序列化 → 合并到本地
```

**关键实现**：

```rust
// crates/sync/src/e2ee/mod.rs
pub struct EncryptedPayload {
    pub version: u8,           // 格式版本
    pub salt: [u8; 16],        // HKDF 盐
    pub nonce: [u8; 12],       // AES-GCM 随机 nonce
    pub ciphertext: Vec<u8>,   // 密文 + GCM 认证标签
}

pub fn encrypt_sync_payload(
    plaintext: &[u8],
    sync_key: &[u8; 32],
) -> Result<EncryptedPayload, AppError> {
    let salt = generate_random_salt();
    let nonce = generate_random_nonce(); // 12 字节
    // 从同步密钥派生实际加密密钥
    let enc_key = hkdf_expand(sync_key, &salt, b"sync-payload")?;
    // AES-256-GCM 加密（同时提供机密性和完整性）
    let ciphertext = aes_gcm_encrypt(&enc_key, &nonce, plaintext)?;
    Ok(EncryptedPayload { version: 1, salt, nonce, ciphertext })
}
```

**关键约束**：

- 每次加密使用**唯一的随机 nonce**（12 字节），严禁复用。
- 同步密钥与数据库密钥通过 HKDF 的 `info` 参数隔离，互不影响。
- GCM 认证标签验证失败时，拒绝数据，不进行部分解密。
- 网络中断时，加密后的数据包可暂存本地，恢复连接后重新上传。

### 5.4 敏感凭证存储

API Key、WebDAV 凭证等不存入数据库，而是通过 OS 原生钥匙串管理。Tauri 环境下使用 `keyring` crate 实现跨平台适配：

```rust
// crates/crypto/src/keyring.rs
pub struct KeyringAdapter;

impl KeyringAdapter {
    pub fn store(service: &str, account: &str, secret: &str) -> Result<(), AppError> {
        let entry = keyring::Entry::new(service, account)?;
        entry.set_password(secret)?;
        Ok(())
    }

```

|---|---|---|

| WebDAV 密码 | OS 钥匙串 | `com.promptmanager.webdav` |
| AI API Key | OS 钥匙串 | `com.promptmanager.openai` 等 |
| 恢复短语 | 用户离线保存 | 不存储 |

### 5.5 应用锁与自动锁定

```rust
// crates/crypto/src/lock.rs
pub struct AppLock {
    locked: AtomicBool,
    last_activity: Mutex<Instant>,
    timeout: Duration,  // 默认 5 分钟
}

impl AppLock {
    pub fn check_and_lock(&self) -> bool {
        let last = self.last_activity.lock().unwrap();
        if last.elapsed() > self.timeout && !self.locked.load(Ordering::Relaxed) {
            self.locked.store(true, Ordering::Relaxed);
            return true;
        }
        false
    }

    pub fn reset_activity(&self) {
        let mut last = self.last_activity.lock().unwrap();
        *last = Instant::now();
    }
}
```

自动锁定触发时，内存中的密钥被 `zeroize` 清零，前端弹出解锁界面。

### 6.3 CRDT 冲突解决

采用 **HLC（Hybrid Logical Clock）+ LWW（Last-Write-Wins）** 策略，实现字段级冲突解决：

```rust
// crates/sync/src/crdt/mod.rs
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct HybridLogicalClock {
    pub wall_time: u64,       // 物理时钟（毫秒）
    pub logical_counter: u32, // 逻辑计数器
    pub device_id: String,    // 设备标识
}

impl HybridLogicalClock {
    /// 比较两个 HLC，确定因果顺序
    pub fn compare(&self, other: &Self) -> Ordering {
        match self.wall_time.cmp(&other.wall_time) {
            Ordering::Equal => match self.logical_counter.cmp(&other.logical_counter) {
                Ordering::Equal => self.device_id.cmp(&other.device_id),
                ord => ord,
            },
            ord => ord,
        }
    }
}

/// 字段级 LWW 合并
pub fn merge_prompt_fields(
    local: &Prompt,
    remote: &Prompt,
    local_hlc: &HybridLogicalClock,
    remote_hlc: &HybridLogicalClock,
) -> Prompt {
    let mut merged = local.clone();
    // 逐字段比较 HLC，较晚的写入胜出
    if remote_hlc.compare(local_hlc) == Ordering::Greater {
        merged.title = remote.title.clone();
        merged.content = remote.content.clone();
        merged.description = remote.description.clone();
    }
    // 版本历史采用追加式合并，不冲突
    merged.versions.extend(
        remote.versions.iter()
            .filter(|v| !local.versions.iter().any(|lv| lv.id == v.id))
            .cloned()
    );
    merged
}
```

**冲突处理策略**：

| 数据类型 | 冲突策略 | 说明 |
|---|---|---|
| 标题、描述 | LWW（HLC 比较） | 较晚的写入胜出 |
| 提示词内容 | LWW + 人工兜底 | 时间接近时弹出对比界面 |
| 版本历史 | 追加式合并 | 不可变日志，直接合并 |
| 标签关联 | 集合并集 | 两端标签取并集 |
| 项目归属 | 集合并集 | 多对多关系，取并集 |

**人工兜底机制**：当同一字段被两端同时修改且 HLC 差值小于阈值（如 5 秒），弹出对比界面让用户选择保留哪个版本，并提供"保留两者为分支"选项。


### 7.5 数据一致性保证

- **本地写入原子性**：所有涉及多表写入的操作（如创建提示词同时写 prompts、versions、tags、projects、sync_log）在同一个 SQLite 事务中完成。
- **同步幂等性**：sync_log 中的每条记录有唯一 ID，重复应用不会产生副作用。
- **版本历史不可变**：prompt_versions 表只允许 INSERT，不允许 UPDATE 或 DELETE。
- **删除软删除**：提示词删除后进入回收站（`deleted_at` 字段标记），版本历史保留，可恢复。

## 8. 部署架构

### 8.1 桌面应用

- **打包**：Tauri CLI 生成 Windows（.msi/.exe）、macOS（.dmg/.app）、Linux（.deb/.AppImage）安装包。
- **自动更新**：通过 Tauri Updater 插件实现，更新包签名验证。
- **数据库位置**：`{app_data_dir}/prompt-manager/vault.db`（SQLCipher 加密）。
- **日志位置**：`{app_log_dir}/prompt-manager/`，按日期轮转。

### 8.2 同步存储

- **方案**：用户自有的 WebDAV 服务器（坚果云、群晖、Nextcloud 等）。
- **不依赖**：不要求自建服务器，不依赖中心化云服务。
- **数据格式**：所有上传文件为 AES-256-GCM 加密后的密文，服务器无法解密。

## 9. 安全威胁模型

| 威胁 | 影响 | 缓解措施 |
|---|---|---|
| 设备丢失 | 数据库文件被直接读取 | SQLCipher 全库加密，OS 钥匙串存储密钥 |
| 同步服务器被攻破 | 提示词内容泄露 | 端到端加密，服务器仅存储密文 |
| 网络中间人攻击 | 同步数据被窃听/篡改 | HTTPS/TLS + AES-GCM 认证加密 |
| API Key 泄露 | 第三方模型被滥用 | API Key 仅存 OS 钥匙串，不落盘 |
| 口令暴力破解 | 主密钥被破解 | Argon2id（64MB 内存，抗 GPU） |
| 内存转储 | 运行时密钥被提取 | `zeroize` 清零敏感内存，自动锁定 |
| 插件/扩展权限过大 | 恶意插件读取数据 | Tauri capabilities 最小权限原则 |
| 恢复短语泄露 | 密钥被恢复 | 用户离线保存，不存储在任何电子设备 |

## 11. 技术风险与应对

| 风险 | 等级 | 应对措施 |
|---|---|---|
| `tauri-plugin-rusqlite2` 为社区维护 | 中 | 关注官方 `tauri-plugin-sql` 的 SQLCipher 支持进展，预留迁移路径；核心数据访问层通过 Repository trait 隔离，更换实现只需替换 storage crate |
| CRDT 合并逻辑复杂 | 中 | 先实现字段级 LWW + HLC，后续按需引入更复杂的 CRDT 类型；版本历史天然追加式，不产生冲突 |
| Nunjucks 为 JavaScript 实现 | 低 | 通过 Tauri 前端侧调用，或在 Rust 侧使用 `tera` 作为备选（API 风格相近） |
| TypeScript 7.0 为 Go 重写版本 | 低 | 若团队对稳定性有更高要求，可暂时保留 TypeScript 6.0 |
| WebDAV 服务商兼容性差异 | 低 | 优先适配坚果云、群晖、Nextcloud，使用标准 WebDAV 方法，避免依赖非标准扩展 |

### 12.2 数据库迁移策略

使用 `rusqlite_migration` 管理数据库版本，每次迁移为一个独立的 SQL 文件：

```
crates/storage/src/migrations/
├── 001_initial.sql
├── 002_add_projects.sql
├── 003_add_sync_log.sql
└── ...
```

迁移在应用启动时自动执行，迁移前自动备份当前数据库文件。

### 12.3 性能优化要点

- **SQLite 索引**：为 `prompts.title`、`prompts.category`、`tags.name`、`prompt_tags.prompt_id` 建立索引。
- **全文搜索**：使用 SQLite FTS5 扩展实现提示词内容的全文检索。
- **前端虚拟滚动**：使用 `@tanstack/react-virtual` 对长列表进行虚拟渲染。
- **IPC 批量操作**：批量操作通过单个命令传入数组参数，减少 IPC 往返次数。
- **流式 AI 输出**：使用 Tauri Channel 实现流式传输，避免等待完整响应。
- **同步增量上传**：只上传 `sync_log` 中未同步的变更，而非全量数据。
