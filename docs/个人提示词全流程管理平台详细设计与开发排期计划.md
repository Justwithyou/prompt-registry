# 个人提示词管理平台 详细设计与开发排期

**文档版本**：V1.0
**日期**：2026-09-28
**状态**：草案
**关联文档**：《个人提示词管理平台 BRD》V1.0、《架构设计方案》V1.0

## 1. 文档概述

### 1.1 文档目的

本文档基于 BRD 与架构设计方案，对 MVP（P0）和 v1.0（P1）功能进行详细设计拆解，并给出可执行的开发排期。排期基于**AI 辅助开发（Claude Code / Cursor） + 成熟模板加速**的假设，实际开发周期将显著短于传统估算。

### 1.2 排期基准与效率假设

传统估算（BRD 中的“1～2 周 / 1～2 个月”）基于纯手工开发。实际开发中采用以下加速策略：

| 加速因素 | 依据 | 预期效果 |
|---|---|---|
| AI 辅助编码 | Simon Willison 单日编码量可达约 1 万行；55% 开发者每周节省至少 7 小时 | 编码工时压缩至 1/3 |
| 生产级模板复用 | armelhbobdad/tauri-template 提供完整的 Tauri v2 + React 19 + TypeScript 脚手架，含多窗口、i18n、主题系统、更新器、命令面板等 | 基础设施搭建从 3 天压缩至半天 |
| 类型安全 IPC | tauri-specta 自动生成 TypeScript 绑定，消除前后端契约手工维护 | IPC 联调工时减少 50% |
| SQLCipher 现成插件 | tauri-plugin-rusqlite2 已支持 SQLCipher、事务、迁移 | 数据库加密集成从 2 天压缩至半天 |
| AI 生成 UI 原型 | ChatGPT / Claude 可快速产出完整 UI 方案 | 原型设计从 2 天压缩至 1 天 |

**排期策略**：以 **“小时” 为单位估算**，而非“天”。按每日有效编码 6 小时计算（扣除评审、调试、会议），所有工时按小时汇总后折算为日历天数。

### 1.3 里程碑与优先级

| 里程碑 | 范围 | 目标日期 | 交付标准 |
|---|---|---|---|
| **M0** | 环境搭建 + 骨架 | Day 1 | `cargo tauri dev` 启动，React 热更新可用 |
| **M1（MVP）** | P0：提示词增删改查 + 本地存储 + 搜索 + 一键复制 | Day 2～3 | 核心闭环可运行 |

### 2.2 MVP 详细设计（M1，约 18 小时）

#### 2.2.1 数据层（4 小时）

**数据库 Schema 设计**：

```sql
-- 核心表
CREATE TABLE prompts (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    description TEXT,
    category TEXT,
    is_pinned INTEGER DEFAULT 0,
    is_favorite INTEGER DEFAULT 0,
    rating INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    deleted_at TEXT
);

CREATE TABLE tags (
    id TEXT PRIMARY KEY,
    name TEXT UNIQUE NOT NULL,
    parent_id TEXT REFERENCES tags(id),
    color TEXT
);

CREATE TABLE prompt_tags (
    prompt_id TEXT REFERENCES prompts(id),
    tag_id TEXT REFERENCES tags(id),
    PRIMARY KEY (prompt_id, tag_id)
);

-- FTS5 全文搜索
CREATE VIRTUAL TABLE prompts_fts USING fts5(
    title, content, description,
    content='prompts', content_rowid='rowid'
);

-- 版本历史
CREATE TABLE prompt_versions (
    id TEXT PRIMARY KEY,
    prompt_id TEXT REFERENCES prompts(id),
    version TEXT NOT NULL,
    content TEXT NOT NULL,
    change_summary TEXT,
    created_at TEXT NOT NULL
);

-- 同步日志
CREATE TABLE sync_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_type TEXT NOT NULL,
    entity_id TEXT NOT NULL,
    operation TEXT NOT NULL,
    payload TEXT,
    hlc TEXT NOT NULL,
    device_id TEXT NOT NULL,
    synced INTEGER DEFAULT 0,
    created_at TEXT NOT NULL
);

-- 索引
CREATE INDEX idx_prompts_category ON prompts(category);
CREATE INDEX idx_prompts_updated ON prompts(updated_at DESC);
CREATE INDEX idx_prompt_tags_prompt ON prompt_tags(prompt_id);
```

**SQLCipher 集成**：

```rust
// crates/storage/src/sqlite/connection.rs
pub fn open_encrypted_db(
    path: &Path,
    master_key: &[u8; 32],
) -> Result<Connection, AppError> {
    let db_key = hkdf_expand(master_key, b"database-encryption-key")?;
    let conn = Connection::open(path)?;
    conn.pragma_update(None, "key", &hex::encode(&db_key))?;
    // 验证密钥
    conn.pragma_query_value(None, "cipher_version", |row| {
        row.get::<_, String>(0)
    })?;
    Ok(conn)
}
```

tauri-plugin-rusqlite2 已支持 SQLCipher，连接字符串格式为 `sqlite:pass:test.db`。

**变量提取**：正则识别 `{{变量名}}`，返回 `VariableDefinition[]`：

```rust
// crates/template/src/extractor.rs
pub fn extract_variables(content: &str) -> Vec<VariableDefinition> {
    let re = Regex::new(r"\{\{(\w+)\}\}").unwrap();
    re.captures_iter(content)
        .map(|cap| VariableDefinition {
            name: cap[1].to_string(),
            default_value: None,
            options: None,
            description: None,
        })
        .collect()
}
```

### 2.5 安全与同步详细设计（M4，约 20 小时）

#### 2.5.1 密钥管理层级（6 小时）

```
用户口令 → Argon2id → KEK (256-bit)
    │
    └── 包装 → Master Key (随机 256-bit)
                  │
                  ├── 加密 SQLCipher 数据库
                  ├── 加密同步数据包
                  └── 存储到 OS 钥匙串
```

**Argon2id 参数**：内存 64MB，迭代 3 次，并行度 1，盐 32 字节。

**密钥轮换**：更换口令时只需重新包装 Master Key，数据加密密钥不变。

#### 2.5.2 端到端加密同步（10 小时）

**加密管道**：

```rust
pub fn encrypt_sync_payload(
    plaintext: &[u8],
    sync_key: &[u8; 32],
) -> Result<EncryptedPayload, AppError> {
    let salt = generate_random_salt();      // 16 字节
    let nonce = generate_random_nonce();    // 12 字节
    let enc_key = hkdf_expand(sync_key, &salt, b"sync-payload")?;
    let ciphertext = aes_gcm_encrypt(&enc_key, &nonce, plaintext)?;
    Ok(EncryptedPayload { version: 1, salt, nonce, ciphertext })
}
```

**WebDAV 客户端**：使用 `reqwest` 实现 PUT/GET/PROPFIND，支持坚果云、群晖、Nextcloud。

**同步流程**：

```
1. 采集 sync_log 中未同步变更
2. 序列化 → AES-256-GCM 加密 → WebDAV PUT
3. WebDAV PROPFIND/GET 拉取远端变更
4. 解密 → CRDT 合并 → 写入本地 SQLite
```

#### 2.5.3 CRDT 冲突解决（4 小时）

采用 HLC + 字段级 LWW：

```rust
pub struct HybridLogicalClock {
    pub wall_time: u64,
    pub logical_counter: u32,
    pub device_id: String,
}

pub fn merge_prompt_fields(
    local: &Prompt,
    remote: &Prompt,
    local_hlc: &HLC,
    remote_hlc: &HLC,
) -> Prompt {
    let mut merged = local.clone();
    if remote_hlc.compare(local_hlc) == Ordering::Greater {
        merged.title = remote.title.clone();
        merged.content = remote.content.clone();
    }
    merged
}
```

版本历史采用追加式合并，不产生冲突。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| WebDAV 服务商兼容性差异 | 同步失败 | 优先适配坚果云、群晖、Nextcloud |
| CRDT 合并边界情况 | 数据丢失 | 先实现字段级 LWW，人工兜底界面 |
| SQLCipher 跨平台编译 | 构建失败 | 使用 `bundled-sqlcipher` feature，锁定 libsqlite3-sys 版本 |
| 模板引擎前端/后端选择 | 渲染不一致 | 优先前端 Nunjucks，Rust 侧保留 tera 备选 |
| AI 生成代码质量 | 引入 bug | 每个模块完成后运行 `cargo clippy` + `vitest`，关键逻辑人工审查 |
